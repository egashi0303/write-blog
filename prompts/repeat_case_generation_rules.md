# Repeat Case Generation Rules

同じ案件情報が再送された場合は、過去記事を確認して、別切り口の記事を生成する。

## 判定ルール

1. `案件ID` が同じ場合は同一案件として扱う。
2. `案件ID` が空欄の場合は `案件名` が同じものを同一案件として扱う。
3. 案件名と同じファイル名の記事出力スプレッドシートが存在する場合、その中の `記事一覧` シートで過去の `切り口`、`記事タイトル`、`記事本文` を確認する。
4. 過去記事と同じ主役の悩み、導入、結論、CTAへの流れを使わない。
5. 新しい記事は、未使用の `切り口` を1つ選んで作成する。

## 案件別シートの保存形式

案件ごとに1つの記事出力スプレッドシートを作成する。
ファイル名は `案件名` とする。
各ファイル内の `記事一覧` シートは、1記事1行で下に追記する。列は `記事作成日 / 案件ID / 案件名 / 切り口 / 記事タイトル / 記事本文 / サムネイルURL` を使う。

列:

- 記事作成日
- 案件ID
- 案件名
- 切り口
- 記事タイトル
- 記事本文

## 切り口の選び方

案件情報に含まれる以下の要素を分解して、過去に使っていないものを優先する。

- 読者の悩み
- 商品・サービスの特徴
- CTA
- 伝えたいこと
- 必須条件
- 季節性
- 利用シーン
- 初心者の誤解
- 行動できない理由

## 重複回避

以下が過去記事と近い場合は、別案に切り替える。

- タイトルの主語や悩みが同じ
- 冒頭の状況描写が同じ
- 本文の中心テーマが同じ
- CTA直前の未来イメージが同じ
- 過去の `切り口` と同じ

## 出力ルール

記事生成後は、案件名と同じファイル名の記事出力スプレッドシート内にある `記事一覧` シートの最終行に追記する。
既存行は上書きしない。

新しい案件が増えた場合は、既存スプレッドシートにシートを追加しない。
必ず案件名の新しいスプレッドシートを作成し、`記事一覧` シートを上記の列構成にする。
案件管理スプレッドシートには記事本文を保存しない。
